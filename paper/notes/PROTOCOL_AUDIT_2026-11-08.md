# Protocol and implementation audit, 8 November 2026

This audit examined the original analysis and feature scripts, saved features,
metadata and result files. Historical code/results were preserved. The new
`revised_protocol.py`, `run_revised_identification.py` and
`run_revision_simulations.py` produce the revised analyses in
`results/wid_revision_2026-11-08/`.

## Verified source facts

- All 336 image-file SHA256 hashes match `dataset/metadata/images.csv`.
  There are 42 writers, 21 per hand, one recorded capture session
  (`2026-10-19`) and one camera model (`Galaxy A17`). Metadata records contain
  no duplicate file or pixel hashes.
- All 5,040 feature unit IDs align exactly with `features/units.csv`.
  The 39 excluded units are strips: one quarter strip and 38 eighth strips.
  All saved handedness logits are finite and writer labels are consistent.
- Handedness SVM scaling and nuisance regression are fitted within the relevant
  training set. Platt calibration uses out-of-fold scores with writer-grouped
  inner folds, inside the held-writer-out training set. The feature extraction
  code and frozen ImageNet checkpoint choices are present locally.
- Original primary probabilistic fusion selects temperature from identity
  scores alone, excluding the scored query writer. It does not tune temperature
  using the attribute scores or scored writer's hand label.

## Changes made for the revision

1. The original identification scaler used all 252 shared paragraphs. For
   shared-text queries this included the questioned paragraph; for one/two/three
   reference conditions it also included shared paragraphs outside the selected
   reference subset. The revised scaler is fitted separately for every
   configuration using only that configuration's selected gallery reference
   paragraphs. No question image contributes.
2. All revised accuracies use one estimand: average reference configurations per
   unit, then units per writer, then give all 42 writers equal weight. Temperature
   losses give development query writers equal weight. The original summaries
   were unit-weighted while paired differences were writer-weighted, creating
   small discrepancies when invalid strips caused unequal unit counts.
3. Exact score ties now follow fixed lexical gallery-writer order. No top-score
   ties occurred in the revised main score matrices. The original strict-greater
   rank function would count every tied maximum as rank one.
4. Gaussian simulation noise is drawn once per distinct question unit and
   reused across reference configurations. The uninformative endpoint uses zero
   log odds and exactly reproduces the baseline under score fusion; hard
   filtering uses a fair random hand decision at that tie. The perfect endpoint
   explicitly equals the oracle. The original script capped nominal accuracy
   one at 0.999 and redrew noise for repeated reference configurations.
5. Revised prevalence analysis, when generated, refits scaling using only the
   selected reduced-gallery references. It retains full-cohort identity-only
   temperature calibration with the scored query writer excluded; this is
   disclosed as a conditional sensitivity analysis.

## Interpretation and limitations requiring disclosure

- `PLAN.md` records that paragraph-level feasibility outcomes were inspected
  before the final analysis protocol. The four named comparisons are designated
  retrospective comparisons; Holm adjustment does not make them preregistered
  confirmatory evidence.
- Writer-bootstrap intervals and sign flips condition on the saved fitted
  evidence, observed references and cohort. They do not refit the complete
  training pipeline or establish generalization to new capture sessions.
- Learned log-linear fusion is outside the revised core. Its original
  development evidence for writer v was generated by a model excluding v but
  potentially including the ultimately scored writer w. Fully nested weight
  tuning would require generating development evidence inside exclusion of w.
- Original both-predicted gallery evidence is a cohort-crossfit diagnostic.
  An impostor v's predictor excludes v but can train on w's shared data and hand;
  the true writer's query and gallery evidence both use the model excluding w.
  This design does not demonstrate metadata-free external deployment.
- The enrolled-model shared-score Platt calibrator is evaluated on the same
  out-of-fold raw-score labels used to fit that calibrator. Its own-text
  evaluation uses separate paragraphs. Random-label controls demonstrate
  learnable writer-label information; they do not decompose real handedness
  accuracy into causal identity and handedness contributions.
- Original random-control spread matching uses all valid units. It is a
  conditional diagnostic, not a prospectively estimated deployment transform.
- The filtering product is an independence approximation. The exact success
  probability is P(correct hand AND oracle identification succeeds); covariance
  between these events must be retained when independence is not established.

## Main implementation checks

The revised run covers 120 settings, 1,152 method summaries and 48,384 writer
outcomes. Every method/setting contains 42 writers. Oracle accuracy is at least
baseline accuracy in every setting, accuracy bounds hold, and summaries equal
the mean of stored writer outcomes to floating-point precision. A direct check
confirmed that changing a held-out writer's true identity targets cannot change
that writer's selected temperature. Each writer has total row weight 1/42.
Run settings and input/source hashes are in `protocol_provenance.json`.
